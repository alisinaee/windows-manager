# Scoped capture and restore (P6.115, Opus plan)
Capture-side scoping exists (WMCore/ProfileMap/CaptureSelection.swift tree Monitor > Space > window, CaptureSelectionSheet in Studio, `wm capture --select app:|desktop:|fullscreen|minimized`). Missing: monitor selector in the CLI, menubar capture selection, and ALL restore scoping.
Model: `RestoreScope` (WMCore/Restore/RestoreScope.swift): displays:Set<String>? (displayUUID), desktops:Set<SpaceRef>? (displayUUID+desktopNumber), apps:Set<String>? (bundle ids); nil = all. Pure `RestoreScope.filter(profile)->Profile`: keep matching windows, plus allDesktops windows when their display is in scope; drop Spaces outside scope; do NOT renumber. Outside scope = untouched (never moved, never closed). Partial scope skips planOtherApps. Launch only apps with windows in scope. Resolve scope after display remap; a missing display warns and targets nothing. addMissingDesktops only for in-scope desktops. Stage Manager absorb only in-scope. Report/plan carry the scope.
UX: capture sheet tree with counts; menubar capture "Choose what to save..."; Studio buttons "Apply this desktop only"/"Apply this monitor only" + scope chip in RestorePreviewSheet; menubar Run <profile> becomes a submenu: Whole profile / Desktop N (Monitor) / Monitor X.
CLI: `wm run|plan --monitor <uuid|name|index> --desktop N --app <bundle|name>` (repeatable; desktop relative to --monitor if given); `wm capture --select monitor:<id>`; empty scope = usage error.
