## P0: broken

### P0-1. Edit-mode map opens at 10%, a tiny cluster in the top-left corner
Screens: studio-edit-selected, studio-dark-edit, studio-light-edit, studio-edit-dirty, inspector-options, inspector-launch, studio-light-launch, save-sheet-conflict, new-profile-refused.
What: the monitors render about 40 px wide at (375,150), and the zoom cluster reads `10%`. Nothing is readable or editable until the user presses Fit.
Cause (`ProfileStudio/ProfileMapModel.swift`):
- `load(_:)` sets `pendingFit = true` and then calls `fit()` straight away, using whatever `viewport` is at that moment. That can be zero or stale, and `fitting` then clamps to the 10% minimum.
- `setViewport(_:)` uses up `pendingFit` on the first size it sees. In Edit, that size is a short-lived one while `makeEditRoom` grows the window and the inspector column is inserted. Later, real sizes never refit.

Fix:
- Replace the one-shot `pendingFit` with `var autoFit = true`. It stays true until the user zooms or pans (set it false in `setZoom`, `zoomBy`, `panBy` and `zoomToSelection` when called from user input, i.e. `CanvasNavigator`, the zoom buttons and the keyboard).
- `setViewport` calls `fit()` on every size change while `autoFit` is true and the size is usable (`width >= 200 && height >= 150`).
- `load(_:)` only fits when the viewport is usable. Otherwise it leaves the fit for `setViewport`.
- `fit()` sets `autoFit = true` again, so pressing Fit restores auto-fit behaviour.

Files: `ProfileMapModel.swift` (`load`, `setViewport`, `fit`, `apply`), `ProfileMapCanvas.swift` (zoom cluster buttons, `.onChange(of: geo.size)`), `CanvasNavigator.swift` (mark user interaction).

### P0-2. Map content disappears or lands off-screen after the window, sidebar or inspector changes size
Screens:
- studio-narrow: the canvas is empty, and the monitors are outside the viewport.
- studio-wide and sidebar-collapsed: the monitors are pushed to the bottom, the "Built-in Retina Display" card sits under the zoom cluster, and the main monitor is cut off by the status line.

What: same root cause as P0-1. The fit is calculated once and never again. The zoom reads `100%` while the content is mis-positioned.
Fix: the `autoFit` rule from P0-1 covers window resizes. Column toggles (sidebar via `Cmd-Opt-S`, inspector) also change `geo.size`, so they refit too. Also keep the content centred when the fit is capped at `maxZoom: 1`: `CanvasViewport.fitting` has to centre the content inside the viewport, not anchor it to the top-left.
Files: `ProfileMapModel.swift`, `ProfileMapCanvas.swift`.

### P0-3. Edit inspector tab bar disappears when switching tabs (user report)
Screens: inspector-* (the captures show it intact; the bug is in live use).
Cause: `StudioEditDetail.inspector` (`ProfileStudioView.swift`) puts the tab bar in a `.safeAreaInset(edge: .top)` on a `Group` that switches between three bodies, each with its own scroll container and sizing:
- `MapInspectorView`: `ScrollView` plus a `Palette.canvas` background.
- `ProfileOptionsPanel`: a grouped `Form`, which is itself a scroll view that wants the whole column.
- `LaunchOrderEditor`: `VStack` + `List(.inset)` + a footer.

On top of that sits `.frame(maxHeight: .infinity).clipped()`. On macOS 26, a `Form` or `List` placed as the direct child of an inset container adopts the safe area and scroll-edge effect itself. Switching tabs swaps the scroll view under the inset, which can lay the bar out under the content or clip it.
Fix: the inspector refactor in Batch A (one container, one `ScrollView`, header pinned with `safeAreaBar`, panels without their own scroll containers). **[SP resize]** "On 26+, attach custom control bars with `safeAreaBar()` instead of … guessing clearance"; **[SP resize]** "prefer TabView and system toolbars … custom bars do not automatically … overflow".

### P0-4. Edit sidebar doesn't scroll (user report)
Screens: none (only 4 rows in the fixtures). Matrix gap: add a fixture with 30+ profiles.
Likely causes, in order:
1. `CanvasNavigator` installs a window-wide `NSEvent.addLocalMonitorForEvents([.scrollWheel, …])` and returns `nil` (swallows the event) whenever it decides the pointer is `inside`. The guard is `bounds.contains(point) && !isOverForeignScrollView(...)`. `isOverForeignScrollView` walks up from `hitTest` looking for an `NSScrollView`. On macOS 26, SwiftUI `List(.sidebar)` isn't guaranteed to be an `NSScrollView` subtree. Also, in Edit there can be two navigators (builder canvas plus the stale view-mode host during the transition), and one may have bounds covering the sidebar.
2. A window taller than the visible screen (the 1631 pt captures) puts the end of the list below the screen edge, so the list "can't" be scrolled to it.

Fix:
- Don't intercept scrolling with a local monitor. Make the navigator an `NSView` that overrides `scrollWheel(with:)` and `magnify(with:)`. AppKit only routes those events to it when it is the hit-tested view, so the sidebar and inspector keep their own scroll.
- Keep the local monitor only for the Space-bar pan key.
- `clampToScreen` also has to run after `makeEditRoom` and after a frame is restored by `UXTestRoute.place`.

Files: `ProfileStudio/CanvasNavigator.swift`, `ProfileStudio/ProfileStudioWindowController.swift`.

### P0-5. Column minimums add up to more than the window minimum (split-view crash class)
Code: `navigationSplitViewColumnWidth(min: 180)`, `StudioEditDetail.libraryAndMap.frame(minWidth: 320)` and `inspectorColumnWidth(min: 260)` add up to **760**. `ProfileStudioWindowController.minSize` is **720**. Add the window chrome and divider widths, and AppKit's split view can't meet every column minimum. That's the "feedback loop" fixed in 5929f27 and worked around with `makeEditRoom` (1400x820).
Fix:
- Remove `.frame(minWidth: 320)` from `libraryAndMap`. The map is the flexible column and needs no minimum.
- Set the inspector to `min: 280, ideal: 300, max: 360` and the sidebar to `min: 200, ideal: 220, max: 300`.
- Raise `minSize` to `900 x 560`, so that the sum of the minimums is below it.
- Remove `makeEditRoom`, or reduce it to a soft "grow if the screen allows" that never exceeds the visible frame.

**[SP design]** "Prefer flexible frames unless a fixed size can comfortably hold the content".
Files: `ProfileStudioView.swift` (Batch A), `ProfileStudioWindowController.swift` (Batch C).

### P0-6. Empty-state window clips its primary button
Screen: studio-sidebar-empty.
What: the window is 400x308 and titled "Profiles". "Capture Current Desktop" is cut off at the left edge, and the orange warning wraps to two long lines. It doesn't look like the Studio window at all.
Fix:
- Keep the normal Studio window size and layout (sidebar with an empty state plus the detail `ContentUnavailableView`) instead of the tiny `noProfiles` window.
- If the separate view is kept, give it `.frame(minWidth: 520, minHeight: 360)` and wrap the action buttons in `ViewThatFits { HStack; VStack }` **[SP resize]** "Give screens that assume everything fits … a `ViewThatFits` fallback".
- Turn the warning into a `Banner(tone: .warning, actionLabel: "Open System Settings")`.
- Use the window title "Profile Studio" everywhere.

Files: `ProfileStudioView.swift` (`noProfiles`), `ProfileStudioWindowController.swift` (title).

### P0-7. Launch-order tab: per-app delays are editable in "At once" mode, where they are ignored
Screens: inspector-launch, studio-light-launch.
What: the mode is "At once", yet each row still shows active `Wait for [First window]`, `then 0 s` and `max 20 s` steppers. The footer then says "delays are ignored". Users edit values that do nothing.
Fix: in `.parallel` mode, hide the wait and delay controls, or show them disabled with a single explanation at the top of the panel. Only show "Longest wait" in sequential mode.
File: `LaunchOrderEditor.swift` (`row(index:item:plan:profile:)`, `footer`).

## Inspector refactor (target design)

Goal: one inspector container for View and Edit, so disappearing headers, overflow and split-view minimum-size loops can't happen again.

Rules:
1. **One container** (`StudioInspector`), used by both `StudioMapHost` and `StudioEditDetail` through the same `.inspector(isPresented:)` call.
2. **Pinned header**: tabs and a title in `safeAreaBar(edge: .top)` (macOS 26), with a fixed height. Never a sibling in a VStack or an inset on a switching Group.
3. **A single `ScrollView` body.** Panels are plain content: no `ScrollView`, `Form`, `List`, `frame(maxHeight:)`, `.clipped()` or custom background of their own.
4. **Optional pinned footer** in `safeAreaBar(edge: .bottom)` (Launch: Add App and total wait).
5. **Fixed column width**: `inspectorColumnWidth(min: 280, ideal: 300, max: 360)`, set once in the container. No `minWidth` anywhere inside the panels. Rows wrap text and never ask for width.
6. **Shared row components** for every panel.
7. **The tab survives mode switches**, stored on `ProfileStudioModel` (not on `StudioEditLocalState`, which is recreated with `.id(builder)`). Each tab keeps its own scroll position (`scrollPosition(id:)`).

```swift
// ProfileStudio/Inspector/StudioInspector.swift
enum InspectorTab: String, CaseIterable, Identifiable { case selection = "Selection", options = "Options", launch = "Launch" }

struct StudioInspector<Body: View, Footer: View>: View {
    @Binding var tab: InspectorTab
    let title: String                    // "Desktop 1", "Safari – Untitled", "Profile options"
    let isEditable: Bool                 // View mode: same panels, read-only
    @ViewBuilder var content: (InspectorTab) -> Body
    @ViewBuilder var footer: (InspectorTab) -> Footer

    var body: some View {
        ScrollView {
            VStack(alignment: .leading, spacing: Spacing.l) { content(tab) }
                .padding(Spacing.m)
                .frame(maxWidth: .infinity, alignment: .leading)
        }
        .id(tab)                                            // fresh scroll per tab, header unaffected
        .safeAreaBar(edge: .top) {

        }

    }
}

.inspector(isPresented: $model.isInspectorShown) {
```
